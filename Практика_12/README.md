# Практическое занятие 12

Методичка по ошибке озаглавлена «Практическое занятие №11» и не задаёт стартовую клетку или разрешённые направления движения. Чтобы задача имела однозначное полиномиальное решение в теме динамического программирования, программа `task1_labyrinth.cpp` использует минимальное явное соглашение:

- старт находится в клетке `(0, 0)`;
- двигаться можно только вправо и вниз, как в задаче предыдущего занятия;
- `P` учитывается один раз при входе в клетку;
- должна присутствовать ровно одна клетка `E`;
- если до выхода добраться нельзя, выводится `-1`.

Ввод: `N M`, затем `N*M` символов `0`, `1`, `P`, `E`. Строки лабиринта можно писать слитно или разделять символы пробелами. Вывод: максимальное число собранных PDF.

Сложность: `O(N*M)` по времени и `O(N*M)` по памяти.

## Сборка

```powershell
g++ -std=c++17 -O2 -Wall -Wextra -pedantic task1_labyrinth.cpp -o task1.exe
```

## Проверка

Файл собран GCC 15 в режиме `-std=c++17 -O2 -Wall -Wextra -pedantic` без предупреждений. На лабиринте

```text
0P000
000P0
P110P
00P0E
```

программа вывела `3`. Для заблокированного выхода в лабиринте `01 / 1E` получен `-1`, для единственной клетки `E` — `0`. Ещё 250 случайных лабиринтов проверены сравнением с независимым динамическим расчётом.
